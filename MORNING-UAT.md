- Phase 1 — True quit-relaunch redock (MT-016): in a real vault, open a terminal (bottom-docked), quit Obsidian normally AND via `pkill -9 Obsidian`, relaunch each time. Why manual: the wdio harness cannot relaunch the host app — the automated coverage simulates serialize→restore in-process (`tests/e2e/bug-001-restore-redock.e2e.ts`).
- Phase 1 — Latent "Loading workspace…" hang watch (MT-016 watch item): during the relaunches above, if Obsidian stalls at "Loading workspace…", capture the console and file it as a new bug — that's the latent pre-fix hang from BUG-001's history, still uncovered by tests. - Phase 2 — True force-quit orphan check (MT-013): in a real vault, open a terminal, note the pty-server PID (`pgrep -f "bin/pty-server"`) and its shell child (`pgrep -P <pty_pid>`), then `pkill -9 Obsidian`. Expect: BOTH PIDs gone within ~5 seconds — that's the new parent-death watchdog (before this fix, orphans lingered indefinitely; launchd never reaps them). One pkill run can double as Phase 1's MT-016 relaunch check. Note: orphans created BEFORE this fix are not cleaned up retroactively — the ones from your dogfooding vault are still running until you kill them or they're respawned from a rebuilt binary. Why manual: the wdio harness can't kill its own host app; the automated test (`tests/unit/parent-death-watchdog.test.ts`) kills a wrapper parent process instead.
- Phase 2 — Hours-scale idle survival: during a normal work session, leave a terminal completely untouched for an hour or more (Obsidian stays open), then type into it. Expect: shell still alive and responsive — the watchdog must never reap a live-but-quiet session. Why manual: the automated pin covers a bounded idle window (seconds); "indefinitely" is a long-running-stability judgment (testing-approach Level 3).
- Phase 3 — Tab close under heavy output feels instant (MT-004 heavy-output round): in a real vault, run `yes` in a plugin terminal, close the tab while it streams. Expect: the close feels instant (no 1–3s hang-around), and `pgrep -f "bin/pty-server"` shows that instance gone within ~1 second. Why manual: the automated coverage (`tests/unit/sigterm-latency.test.ts`, hygiene AC3 at the tightened 1s budget) SIGTERMs a standalone binary — the real path goes through Obsidian's leaf close, and "feels instant" is a perception judgment. Note: rebuild/reinstall the plugin binary first (`npm run build` refreshes `bin/pty-server`) — an old binary still running in your vault predates the fix.
- Phase 1 — No fighting deliberate moves / drags (MT-017): drag the docked terminal tab next to a note and confirm it stays there for the session (no snap-back); wiggle a pane-resize divider right after relaunch and confirm the redock never interrupts or steals focus mid-drag; a terminal parked in a popout window should be left untouched after relaunch.
